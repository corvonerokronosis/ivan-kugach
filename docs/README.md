# Документация проекта

В корне `docs/` находятся только документы, которые нужны для работы с текущим
Astro-приложением. Историю завершённой миграции и прежние продуктовые черновики
не дублируем: при необходимости они доступны в Git.

## С чего начинать

1. `PROJECT_MAP.md` — карта актуального кода и маршрутов.
2. Профильный документ из таблицы ниже.
3. Текущий код в `src/` — окончательный источник правды при расхождениях.

## Активные документы

| Документ                      | Назначение                                                             |
| ----------------------------- | ---------------------------------------------------------------------- |
| `PROJECT_MAP.md`              | Точки входа, структура проекта и маршрутизация задач                   |
| `LOCAL_CONTENT_GUIDE.md`      | Изменение локальных работ, серий, narrative, hotspots и изображений    |
| `NARRATIVE_ROUTE_CONTRACT.md` | URL и browser-history последовательного интерактивного маршрута        |
| `IMAGE_INVENTORY.md`          | Production-изображения и их использование                              |
| `PERFORMANCE_BUDGET.md`       | Автоматические лимиты production-сборки и ручные ориентиры             |
| `QA_CHECKLIST.md`             | Ручной release-проход по production preview                            |
| `QA_VIEWPORTS.md`             | Матрица целевых viewport и зафиксированные результаты visual QA        |
| `LEGACY_REFERENCE.md`         | Статус архивного прототипа, functional reference и индекс baseline PNG |

## Правила поддержки

- Новую документацию добавляем только при наличии отдельной устойчивой задачи,
  которую не покрывают код, `README.md` или существующий профильный документ.
- Историю итераций оставляем Git, а не отдельным `CHANGELOG_0XX.md`.
- Завершённые планы и одноразовые аудиты удаляем после переноса актуальных
  ограничений в рабочие документы.
- При изменении маршрутов, структуры, команд или источников данных обновляем
  `PROJECT_MAP.md` и соответствующий профильный документ в той же задаче.
- Сырые интервью, стенограммы и brainstorming не храним среди активной
  технической документации.
