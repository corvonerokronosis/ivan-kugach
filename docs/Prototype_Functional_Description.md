# Описание функционала прототипа

Ниже зафиксировано актуальное состояние прототипа проекта на текущий момент. Документ описывает уже реализованную структуру, доступные сценарии, состав экранов и набор экспериментальных визуальных веток, которые существуют в корне проекта как самостоятельные HTML-файлы.

## 1. Общая идея прототипа

Прототип моделирует цифровой музейный опыт вокруг произведений Ивана Кугача. Пользователь не просто просматривает статичную страницу, а проходит небольшой интерактивный маршрут:

1. попадает на посадочный экран;
2. выбирает один из режимов входа в опыт;
3. взаимодействует с картиной через один из интерактивных сценариев;
4. получает narrative-вставки между этапами;
5. возвращается к посадочному экрану или продолжает исследование.

Основная цель прототипа:

- проверить композицию маршрута;
- проверить набор интерактивных механик;
- проверить подачу narrative-переходов;
- протестировать разные визуальные стили на одной и той же логике.

## 2. Текущее состояние проекта

В проекте есть базовый рабочий прототип и несколько визуальных/механических экспериментальных файлов.

### 2.1. Базовый файл

- `index.html` — основной прототип с рабочей структурой экранов и сценариев.

### 2.2. Дополнительные экспериментальные варианты

- `index_immersive_art_installation.html` — экспериментальный вариант в более ярком, атмосферном, иммерсивном стиле;
- `index_turgor_like.html` — отдельный мрачный органический визуальный эксперимент;
- `index_theatre_gallery.html` — отдельная ветка с более театральной музейной подачей;
- `index_art_journal.html` — отдельная ветка с editorial-подачей;
- также в корне лежат предыдущие экспериментальные и промежуточные HTML-файлы, отражающие отдельные направления разработки механик и визуала.

## 3. Реализованный маршрут пользователя

На актуальном этапе пользовательский маршрут устроен так:

1. пользователь открывает посадочный экран;
2. видит hero-блок, краткое описание и карточки входа в интерактив;
3. выбирает один из двух сценариев:
   - сценарий раскрытия цвета;
   - сценарий исследования деталей;
4. при необходимости проходит narrative-блок перед интерактивом;
5. попадает в выбранный интерактив;
6. завершает этап и получает следующий narrative-переход;
7. при прохождении сценария исследования может открыть финальный narrative-блок;
8. возвращается на главную страницу.

## 4. Посадочный экран

Посадочный экран уже не является простой заглушкой. В нём реализованы:

- hero-секция;
- CTA-кнопки;
- карточки входа в два интерактива;
- краткие информационные блоки;
- адаптивная раскладка для desktop и mobile.

### 4.1. Два сценария входа

На посадочном экране доступны две основные карточки:

- `Возвращение цвета` — вход в интерактив раскрытия живописи;
- `Приблизить детали` — вход в режим исследования второй картины.

Карточки содержат:

- название сценария;
- миниатюру изображения;
- короткое описание;
- поясняющий нижний блок с дополнительным текстом.

## 5. Narrative-система

В прототипе реализована narrative-система, связывающая экраны в единый маршрут.

### 5.1. Текущее поведение

Narrative-блоки:

- выводятся на отдельном экране;
- переключаются кнопками `Назад`, `Далее`, `Пропустить блок`;
- используют одну и ту же карточечную структуру;
- могут вести в следующий интерактивный экран;
- могут завершать маршрут возвратом на главную страницу.

### 5.2. Последовательности

Сейчас в коде предусмотрены narrative-последовательности:

- вступление перед первым интерактивом;
- промежуточный переход после раскрытия цвета;
- финальный блок после исследования деталей.

### 5.3. Состав narrative-экрана

Narrative-экран включает:

- заголовочную зону;
- основную narrative-карточку;
- изображение;
- подпись к изображению;
- основной текст;
- дополнительный текстовый блок;
- навигационные кнопки;
- прогрессовый блок последовательности.

## 6. Интерактив `Возвращение цвета`

Первый интерактив построен вокруг механики постепенного проявления цветной картины.

### 6.1. Что реализовано

- загрузка изображения `Kugach_picture_1.png`;
- вывод изображения через canvas;
- отдельный серый слой поверх картины;
- механика стирания серого слоя кистью;
- отслеживание покрытия и прогресса;
- progress bar;
- HUD-блок с подсказками;
- автоматическое завершение при достижении порога;
- финальная автоанимация раскрытия;
- модальное окно после завершения;
- возможность повторить интерактив.

### 6.2. Поведение кисти

Кисть:

- следует за курсором/пальцем;
- работает через pointer events;
- оставляет мягкий радиальный след;
- раскрывает цветной слой;
- участвует в подсчёте прогресса.

### 6.3. Завершение сценария

После достижения целевого порога:

- прогресс доводится до 100%;
- запускается автоматическая анимация финального раскрытия;
- открывается модальное окно;
- пользователь может перейти дальше по маршруту или повторить этап.

## 7. Интерактив `Исследование деталей`

Второй интерактив построен как свободный просмотр картины с зумом и точками взаимодействия.

### 7.1. Что реализовано

- загрузка изображения `Kugach_picture_2.png`;
- масштабирование изображения;
- панорамирование (`pan`) внутри viewport;
- ручной zoom кнопками;
- zoom колёсиком мыши;
- сброс масштаба;
- точки интереса (`hotspots`);
- автоматическое центрирование на выбранной точке;
- модальное окно с текстом по точке;
- подсчёт открытых точек;
- отдельное завершение сценария после открытия всех точек.

### 7.2. Hotspots

Hotspots:

- создаются в JS из массива конфигурации;
- имеют координаты, label, title, text и targetScale;
- могут быть активированы по клику;
- при наведении показывают подпись;
- для точек у нижней границы подпись автоматически выводится сверху, чтобы не выходить за пределы зоны просмотра.

### 7.3. Завершение сценария исследования

После открытия всех точек:

- обновляется текст прогресса;
- открывается кнопка перехода к финальному narrative-блоку;
- дополнительно может появиться модальное окно завершения сценария;
- пользователь может остаться в режиме свободного просмотра или перейти дальше.

## 8. Модальные окна

В прототипе реализованы несколько типов модальных окон:

- модальное окно после завершения раскрытия цвета;
- модальное окно описания выбранной точки исследования;
- модальное окно завершения сценария исследования.

Общее поведение:

- блокировка фонового скролла через `body.modal-active`;
- закрытие по `Escape`;
- закрытие по клику вне карточки;
- управление фокусом для кнопок внутри модалки.

## 9. Адаптивность

Прототип адаптирован под desktop и mobile.

Реализовано:

- перестройка сеток и topbar-блоков на узких экранах;
- адаптация размеров карточек и внутренних отступов;
- адаптация размера кисти;
- перестройка narrative-layout на больших и малых экранах;
- пересчёт размеров canvas и viewport при `resize`.

## 10. Визуальные эксперименты

Помимо базового сценарного прототипа, в проекте появились отдельные стилистические ветки.

### 10.1. `index_immersive_art_installation.html`

Реализует:

- более яркий, насыщенный, атмосферный визуальный стиль;
- свечение, стеклянные поверхности, цветовые ореолы;
- более сложные декоративные слои;
- усиленные stage-экраны;
- более выразительные HUD, hotspots, narrative и модалки.

### 10.2. `index_turgor_like.html`

Реализует:

- более мрачную, органическую, тревожную подачу;
- землисто-болотную палитру;
- более живые и неровные формы блоков;
- более плотную и тяжёлую атмосферу экранов;
- отдельную стилистическую интерпретацию того же маршрута.

## 11. Используемые ресурсы

Основные изображения:

- `Kugach_picture_1.png` — используется в сценарии раскрытия цвета и во вступительных/финальных narrative-вставках;
- `Kugach_picture_2.png` — используется в сценарии исследования деталей и связанных narrative-переходах.

Основные документы:

- `Prototype_Functional_Description.md` — актуальное описание проекта;
- `Narrative_system_requirements.md` — требования к narrative-системе;
- `CHANGELOG.md`, `CHANGELOG_020`, `CHANGELOG_030` — история итераций разработки.

## 12. Технические особенности

На текущем этапе прототип:

- является одностраничным HTML-прототипом;
- не использует отдельный build-step;
- не подключает внешние зависимости;
- держит разметку, стили и логику в одном файле для каждой экспериментальной ветки;
- ориентирован на быстрые продуктовые и визуальные итерации.

## 13. Что уже можно считать реализованным

К текущему моменту реализованы и доступны для проверки:

- целостный маршрут от посадочного экрана до финального narrative-блока;
- два отдельных интерактивных сценария;
- narrative-переходы между этапами;
- модальные окна;
- адаптивная вёрстка;
- система прогресса для обоих интерактивов;
- несколько альтернативных визуальных направлений, оформленных как отдельные HTML-файлы.

## 14. Что остаётся зоной дальнейшего развития

Следующие шаги могут включать:

- замену временных narrative-текстов на финальные кураторские тексты;
- уточнение музейного контента для модальных окон и точек исследования;
- дальнейшее развитие визуальных веток;
- выбор одного style-direction для последующей консолидации;
- при необходимости перенос прототипа из single-file формата в более структурированный фронтенд-проект.
