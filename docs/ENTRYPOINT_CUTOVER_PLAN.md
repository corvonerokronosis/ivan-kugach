# План переключения основной точки входа

Документ устраняет двусмысленность между полнофункциональным legacy-прототипом и создаваемой Astro-версией. Само переключение выполняется только в FRT-062.

## Статус точек входа сейчас

| Роль                               | Путь                                              | Статус до FRT-062                                                                           |
| ---------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Текущая полнофункциональная версия | `index_masterskaya.html`                          | Единственный источник реализованного пользовательского поведения и legacy-эталон            |
| Новая candidate-версия             | `src/pages/index.astro` → `/` в Astro dev/preview | Техническая точка входа миграции; ещё не production-главная                                 |
| Production output Astro            | `dist/index.html`                                 | Generated-файл; создаётся `npm.cmd run build`, не редактируется вручную и не хранится в Git |

Правила переходного периода:

- корневой `index_masterskaya.html` не переименовывается в `index.html`;
- новый рукописный корневой `index.html` не создаётся;
- generated `dist/index.html` не считается второй исходной реализацией;
- до FRT-062 документация называет legacy-файл текущей полнофункциональной версией, а Astro `/` — candidate-версией;
- новые страницы и сценарии реализуются только в Astro-контуре; legacy меняется лишь для критического исправления эталона по отдельной задаче;
- visual baseline и functional checklist продолжают ссылаться на legacy независимо от готовности отдельных Astro-страниц.

## Когда Astro становится основной версией

Переключение разрешено только внутри FRT-062 после завершения всех её зависимостей:

- FRT-054 — объяснены все визуальные отличия от legacy;
- FRT-058 — единая release-проверка выполняется на чистой рабочей копии;
- FRT-059 — README описывает Astro как основной workflow;
- FRT-060 — готова инструкция по локальному контенту;
- FRT-061 — пройден ручной QA-checklist.

Дополнительные обязательные gates:

- все актуальные экраны и три интерактива из functional checklist перенесены;
- целевые URL открываются напрямую и после refresh;
- production preview не зависит от `index_masterskaya.html`;
- маршруты загружают только собственные клиентские модули;
- desktop/mobile и modal/completion-состояния сопоставлены с `docs/VISUAL_BASELINE.md`;
- нет блокирующих runtime, accessibility, TypeScript, lint, content или build-ошибок;
- зафиксирован способ публикации содержимого `dist/`; выбор конкретного хостинга остаётся вне frontend-бэклога.

Если хотя бы один gate не выполнен, статус точек входа не меняется.

## Операция переключения в FRT-062

В одном отдельном коммите:

1. Выполнить `npm.cmd run verify`.
2. Открыть production preview и пройти `docs/QA_CHECKLIST.md`, который будет создан в FRT-061.
3. Убедиться, что сборка не читает и не копирует `index_masterskaya.html`.
4. Переместить файл в `archive/index_masterskaya.html`.
5. После перемещения исправить его legacy-пути `src/...` на `../src/...`, чтобы архивный эталон можно было открыть отдельно.
6. Повторно проверить существование всех изображений, на которые ссылается архивный HTML.
7. Объявить `src/pages/index.astro` и Astro route `/` единственной исходной главной страницей.
8. Объявить `dist/index.html` единственной generated production-точкой входа.
9. Обновить README, `AGENTS.md`, `PROJECT_MAP.md`, functional checklist и visual baseline: legacy должен быть явно обозначен как архив.
10. Зафиксировать в backlog дату переключения и commit hash.
11. Повторно выполнить `npm.cmd run verify` и production preview после перемещения.

Не удалять `experiments/`, старые файлы `archive/` или baseline PNG в рамках переключения.

## Статус после FRT-062

| Роль             | Путь                             | Итоговый статус                                           |
| ---------------- | -------------------------------- | --------------------------------------------------------- |
| Исходная главная | `src/pages/index.astro`          | Единственная поддерживаемая главная страница              |
| Production entry | `dist/index.html`                | Генерируется Astro build и публикуется вместе с `dist/`   |
| Legacy-эталон    | `archive/index_masterskaya.html` | Исторический reference; не участвует в build и production |

После переключения запрещено:

- восстанавливать корневой legacy HTML как альтернативную production-главную;
- редактировать `dist/index.html` вручную;
- поддерживать два разных production-маршрута `/` из разных исходников;
- использовать архивный HTML как источник новых продуктовых изменений.

## Откат

До production-деплоя откат выполняется обычным revert коммита FRT-062.

Если проблема обнаружена после публикации:

1. вернуть предыдущий проверенный `dist/` средствами deployment-процесса;
2. не объявлять архивный HTML новой production-версией без отдельного аварийного решения;
3. исправить Astro-контур, повторить release-проверку и снова опубликовать generated output.

Конкретный deployment rollback будет описан на отдельном этапе выбора хостинга.
