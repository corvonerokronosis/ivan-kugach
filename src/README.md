# Структура исходников Astro

Эта директория содержит новый production-контур. Полнофункциональный legacy-прототип по-прежнему находится в корневом `index_masterskaya.html`.

## Ответственность директорий

| Путь          | Что хранить                                                        | Что не хранить                                       |
| ------------- | ------------------------------------------------------------------ | ---------------------------------------------------- |
| `assets/`     | Импортируемые Astro изображения, шрифты и другие web-ассеты        | Документы, эксперименты и исходники вне frontend     |
| `components/` | Повторно используемые `.astro`-компоненты                          | Данные каталога и глобальное состояние               |
| `content/`    | Записи Astro Content Collections                                   | Логику интерактивов и UI-компоненты                  |
| `data/`       | Типизированные локальные конфигурации и временные источники данных | DOM-обработчики и разметку страниц                   |
| `layouts/`    | Общий HTML-каркас страниц                                          | Данные отдельных страниц                             |
| `pages/`      | Файловые маршруты и композицию страниц                             | Собственные глобальные стили и большие наборы данных |
| `scripts/`    | Изолированные клиентские DOM/Canvas-модули                         | Код, общий для всех страниц без необходимости        |
| `styles/`     | Токены, глобальные стили и общие utilities                         | Стили старого монолита одним большим файлом          |
| `types/`      | Общие TypeScript-типы и интерфейсы                                 | Runtime-данные                                       |
| `utils/`      | Чистые вспомогательные функции и адаптеры                          | Скрытое глобальное состояние                         |

Файлы, которые должны отдаваться без обработки Astro, размещаются в корневом `public/`. Документация остаётся в `docs/`, визуальные эксперименты — в `experiments/`, история — в `archive/`.

## Правила именования

- Astro-компоненты и layouts: `PascalCase.astro`, например `ArtworkCard.astro`.
- Страницы и route-сегменты: lowercase kebab-case, например `color-return.astro`.
- TypeScript-, data-, style- и utility-модули: lowercase kebab-case, например `light-works.ts`.
- Экспортируемые типы и интерфейсы: PascalCase; функции и переменные: camelCase; константы: camelCase, если внешний контракт не требует другого.
- Контентные slug и имена web-ассетов: lowercase kebab-case без пробелов.
- Файлы одной фичи группируются по предметной области, а не по экрану, который случайно использует их первым.

## Границы страниц

- Страница в `pages/` собирает layout и компоненты, но не хранит крупные массивы данных.
- Глобальные стили подключаются через layout; локальный `<style>` допустим только для изолированной разметки компонента.
- Обычная страница использует `BaseLayout.astro`, передаёт `title` и `description`, а содержимое header/footer размещает в одноимённых slots.
- В основном slot страницы должен быть ровно один `<h1>`; самостоятельные разделы продолжают иерархию с `<h2>`, вложенные подразделы — с `<h3>` без пропуска уровней.
- Данные читаются через функции слоя данных, а не напрямую из UI-компонентов.
- Клиентский модуль подключается только на странице соответствующего интерактива и предоставляет явную очистку обработчиков.

## Общие UI-компоненты

- Базовые переиспользуемые элементы лежат в `components/common/`.
- Компоненты получают содержимое и состояние через типизированные props и slots; они не ищут элементы через `document` и не изменяют глобальный DOM.
- `DialogShell.astro` отвечает только за семантическую оболочку нативного `<dialog>`; полноценное управление фокусом и открытием относится к FRT-041.
- Ручная композиционная проверка компонентов доступна на техническом маршруте `/ui-preview/`. Не использовать этот маршрут как продуктовую страницу или источник контента.

## Временное legacy-исключение

Изображения, которые уже лежат непосредственно в `src/`, `src/for_sales/` и `src/picture_light_shadow/`, пока не перемещаются: их строковые пути использует `index_masterskaya.html`. Они будут перенесены в новую asset-структуру отдельной задачей с одновременной проверкой всех ссылок.
